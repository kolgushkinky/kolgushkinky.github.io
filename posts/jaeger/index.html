I have a Telegram echo-bot written in Go, running locally on my laptop. As a DevOps/SRE enthusiast, I wanted to enhance it with logging and observability. After seeing OpenTelemetry mentioned in several job postings, I decided to configure it to add observability to my project.

OpenTelemetry offers two main options for instrumentation:

  1. Zero-code instrumentation: Automatic and minimal setup.
  2. Code-based instrumentation: Requires modifications to the codebase.

I chose the first option for its simplicity and ease of use.

To get started with OpenTelemetry’s zero-code instrumentation for Go, I followed the documentation available on GitHub. The setup was straightforward:

sudo OTEL_GO_AUTO_TARGET_EXE=/home/bin/service_executable OTEL_SERVICE_NAME=my_service OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 ./otel-go-instrumentation However, I soon realized that I needed a collector and a visualization service for my traces and metrics. I considered two options:

  1. Prometheus + Grafana: For collecting and visualizing metrics.
  2. Jaeger: For trace collection.

I decided to start with Jaeger. To run Jaeger using Docker, I used the all-in-one image. The version 1.59 documentation lists various ports, and the docker-compose file provides detailed comments on port usage:

4317:4317 # OpenTelemetry Protocol (OTLP) over gRPC 4318:4318 # OpenTelemetry Protocol (OTLP) over HTTP`

To start Jaeger, I ran:

docker run -d --name jaeger -e COLLECTOR_OTLP_ENABLED=true -p 4317:4317 -p 4318:4318 -p 16686:16686 -p 14269:14269 jaegertracing/all-in-one:1.59 Despite this setup, I encountered a connection reset by peer error. Checking the logs: {"level":"info","ts":1722799839.4332669,"caller":"app/server.go:318","msg":"Starting GRPC server","port":16685,"addr":":16685"} {"level":"info","ts":1722799839.4332783,"caller":"app/server.go:299","msg":"Starting HTTP server","port":16686,"addr":":16686"}

I changed OTEL_EXPORTER_OTLP_ENDPOINT to port 16686, though the Jaeger UI remained unchanged. Further reading in the compatibility documentation revealed that my application does not use any of the supported libraries:

  • database/sql
  • github.com/segmentio/kafka-go
  • google.golang.org/grpc
  • net/http

As mentioned in a Medium article, there might be limitations in the native support for OpenTelemetry, suggesting the use of the OpenTelemetry Collector for more comprehensive observability.
